# Реальный TEST E2E в обычном браузере Windows

## Почему Playwright получает 600010

Cloudflare относит семейство `600*` к generic challenge failure / обнаружению
бот-поведения. Это не отдельный код «неверный sitekey»: для ключа и hostname
документированы другие коды. [Официальный список ошибок](https://developers.cloudflare.com/turnstile/troubleshooting/client-side-errors/error-codes/).

Cloudflare прямо предупреждает о блокировке браузеров Playwright/Selenium
при настоящих challenges. Поэтому Playwright — вероятный фактор в этом случае,
а не доказанная единственная причина. Обновление страницы не убирает
автоматизированное окружение. [Проверки Turnstile и автоматизация](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

`preview-rsvp.mjs --test-api` больше не запускает такой тест: он направляет
к этой инструкции. Локальный `npm run preview` остаётся доступен с локальными
Worker/D1 и моками внешних сервисов. Его успех не доказывает реальный E2E.
Dummy sitekey нельзя смешивать с настоящим secret удалённого TEST Worker.

## Выбранный способ: Local Overrides только HTML

Используем обычный Edge/Chrome, запущенный **вручную из меню Windows**.
DevTools заменяет только тело главного HTML-документа локальной копией PR #8.
Origin остаётся `https://zakkhorren.github.io`; реальный Turnstile загружается
с Cloudflare, а запросы идут напрямую в существующий TEST API.

Не используется Playwright, CDP-подключение, stealth, замена user-agent,
webdriver или токенов, прокси запросов, отключение CORS/CSP/Siteverify.
API-ответы и ресурсы Turnstile не переопределяются. Это стандартная функция
[Local Overrides в Edge](https://learn.microsoft.com/en-us/microsoft-edge/devtools/javascript/overrides)
и [Chrome](https://developer.chrome.com/docs/devtools/overrides/).

Новый файл собирает **существующие** HTML/CSS/JS и модули анкеты без изменения
их логики. Модули включены как data-URL, чтобы не требовалось публиковать новые
`.mjs` или переопределять MIME у ответов 404. Фотографии и шрифты загружаются
обычным способом. Ничего не загружается на GitHub Pages или Cloudflare.

Изменений тестовой инфраструктуры для этого способа не требуется.

## Подготовка

1. Получите актуальную ветку `feat/rsvp-preview` в чистом worktree. Если в
   старой копии есть ручные правки, оставьте её без изменений:

   ```powershell
   git fetch origin
   git worktree add --detach ../wedding-rsvp-manual origin/feat/rsvp-preview
   cd ../wedding-rsvp-manual
   ```

2. Нужны Node.js 24+ и обычный обновлённый Edge/Chrome. Для подготовки HTML
   установка Playwright/Miniflare не нужна.

3. Возьмите **публичный sitekey существующего TEST Managed Turnstile**.
   Он должен соответствовать secret, уже настроенному в TEST Worker.
   В настройках виджета проверьте hostname `zakkhorren.github.io` **без изменения
   настроек**. Если hostname отсутствует — остановитесь и согласуйте исправление
   именно тестового виджета. Не присылайте и не вставляйте secret.

4. Подготовьте локальный документ:

   ```powershell
   node scripts/manual-rsvp-preview.mjs --sitekey ВАШ_ПУБЛИЧНЫЙ_TEST_SITEKEY
   ```

   Скрипт ничего не запускает и не отправляет. Он создаёт:
   - `.qa/manual-turnstile/preview.html` — локальную сборку текущего сайта;
   - `.qa/manual-turnstile/overrides` — отдельную папку Overrides.

   **Не открывайте preview.html через file:// или localhost:** это другой
   origin. Файл содержит публичный sitekey и не входит в Git.

## Настройка обычного браузера

5. Закройте окно старого Playwright preview. Откройте Edge/Chrome вручную.
   Для независимости можно создать обычный отдельный профиль через меню
   браузера. Не включайте эмуляцию устройства или подмену сетевых параметров.

6. Перейдите строго на:

   `https://zakkhorren.github.io/wedding/?rsvp_preview=1`

   Пока override не применён, опубликованный сайт остаётся прежним демо.
   Пока ничего не отправляйте.

7. Нажмите **F12 → Sources / Источники → Overrides / Переопределения**.
   При необходимости раскройте скрытые вкладки через `>>`.
   Выберите **Select folder for overrides** и укажите полную папку
   `.qa/manual-turnstile/overrides`, путь к которой вывел скрипт.
   Нажмите **Allow / Разрешить**. Должен быть включён **Enable Local Overrides**.
   Используйте эту отдельную пустую папку, не весь репозиторий и не старую
   папку отладки с другими файлами.

8. В **Network / Сеть** выберите фильтр **Doc**, обновите страницу.
   Щёлкните правой кнопкой **главный Document** с адресом из шага 6:
   **Override content / Переопределить содержимое**.
   Не выбирайте Override headers. Не выбирайте iframe Turnstile или API-запрос.

   DevTools сам создаст правильное имя файла с query-параметром. Поэтому
   вручную угадывать или переименовывать файл в Windows не нужно.

9. Вернитесь в PowerShell этой же копии проекта:

   ```powershell
   node scripts/manual-rsvp-preview.mjs --apply
   ```

   Обновится только сохранённый DevTools главный документ. Его исходная копия
   останется в `.qa/manual-turnstile/original-document.html`.
   Скрипт откажется работать, если папка содержит дополнительные файлы,
   заголовки или ресурсы других хостов. Ничего автоматически не удаляет.

10. Оставьте DevTools открытым и нажмите **Ctrl+F5**. У главного Document
    должен появиться фиолетовый индикатор Override. У ресурсов
    `challenges.cloudflare.com` и тестового API такого индикатора быть не должно.
    Форма должна показывать «Предварительная версия: ответы отправляются
    только в тестовую базу», привычный дизайн и настоящую проверку Cloudflare.

## Ручная цепочка: сайт → TEST Worker → TEST D1 → TEST Telegram

11. Перед отправкой проверьте, что запросы формы направлены именно в
    `https://wedding-rsvp-api-test.zakk-horren.workers.dev/rsvp`, а его
    существующий binding DB и бот — тестовые. Настройки не меняйте.
    Не сохраняйте HAR, тела запросов, Authorization или персональную ссылку
    в общий отчёт.

12. Заполните одну тестовую компанию с уникальным именем, например
    «E2E вручную — дата/время». Выберите количество людей и парковку.
    Пройдите настоящий Turnstile **вручную** и отправьте форму один раз.
    Успех — красивая карточка «Спасибо за ответ!» / «Ваш ответ сохранён.»
    после `saved:true`, а не просто успешный challenge.

13. Проверьте сообщение **тестового** Telegram-бота. В TEST D1 можно выполнить
    только чтение, без хешей/ключей:

    ```sql
    SELECT id,name,attending,guest_count,parking_choice,cars_requested,
           parking_status,revision,created_at,updated_at
    FROM rsvp_responses
    WHERE archived_at IS NULL
    ORDER BY updated_at DESC
    LIMIT 10;
    ```

    В базе могут оставаться прежние тестовые записи — не очищайте их.
    Найдите именно свою компанию и проверьте число людей/машин.

14. Нажмите «Изменить ответ», измените сообщение или количество людей и
    сохраните. Должны обновиться **тот же ID** и revision, а в тестовом боте
    появиться уведомление об изменении. Не должно добавиться второй компании.
    Обновите страницу с открытым DevTools — ответ должен восстановиться.
    Проверьте копирование персональной ссылки. На другом компьютере/в другой
    чистой копии сначала повторите настройку Overrides, затем откройте ссылку
    в адресной строке; не вставляйте её в терминал.

15. При сетевой ошибке пользуйтесь «Повторить попытку», не создавайте новую
    анкету. Проверку удаления/очистки данных этот сценарий не выполняет.
    Завершив тест, снимите **Enable Local Overrides** и обновите страницу:
    обычный публичный сайт снова должен показывать демо.
    Это не удаляет ответы, локальные ключи или данные в TEST D1.

## Если ошибка остаётся

- `600*` в **обычном** браузере ещё не доказывает проблему приложения.
  Сверьте дату/время Windows, версию браузера, расширения и сеть по
  [рекомендациям Cloudflare](https://developers.cloudflare.com/turnstile/troubleshooting/client-side-errors/error-codes/).
  Зафиксируйте код, время, браузер и Ray ID, если он есть; не публикуйте токены
  и персональные ссылки.
- Для `110100/110110` проверьте публичный sitekey, для `110200` — разрешённый
  hostname. Не заменяйте real secret на dummy secret.
- Не включайте `--disable-web-security`, stealth/антидетект, подмену токенов,
  wildcard CORS или Override ответов Siteverify/API.
- Если Console сообщает о CSP, запрещающем inline/data-модули, **не отключайте
  CSP**. Нужен согласованный staging-host.
- Если после refresh остался демо-режим, проверьте точный URL с
  `?rsvp_preview=1`, выбранный главный Document и включённые Overrides.

## Альтернатива: отдельный staging, только после согласования

Если Local Overrides не подходит, следующий вариант — приватный статический
preview-host этой ветки в обычном браузере. До создания ресурсов нужно отдельно
согласовать: hostname/доступ к preview, TEST `ALLOWED_ORIGIN`, разрешённый
hostname существующего тестового Turnstile (или отдельный тестовый виджет).
API должен продолжать проверять реальный Siteverify и точный hostname.
Production Worker/D1/бот и основной GitHub Pages не затрагиваются.
Эти изменения **не выполнены** и в текущую подготовку не входят.

## Что проверено разработчиком и что остаётся человеку

- Прочитан комментарий PR #8 и официальные документы; причина связи с
  Playwright подтверждается документацией, но единственная причина 600010
  у владельца не установлена.
- Без записи данных проверен OPTIONS существующего TEST API:
  `204`, origin `https://zakkhorren.github.io`, разрешены GET/POST/OPTIONS
  и Content-Type/Authorization. У опубликованной страницы HEAD вернул
  `200`, CSP HTTP-заголовок при проверке отсутствовал.
- Unit-тесты проверяют упаковку неизменённого клиента, отсутствие моков/
  browser-stealth в подготовленном HTML, отказ от dummy sitekeys и ограничение
  apply единственным главным документом.
- Браузерный **транспортный** тест проверяет загрузку сборки без 404 модулей,
  прежнюю форму, создание/восстановление/редактирование одной записи и
  естественный browser Origin через **локальный** Worker/D1. В этой автоматике
  challenge замокан; это не доказательство реального Turnstile или Telegram.

Реальное прохождение Turnstile и доставка в TEST Telegram пока **не подтверждены
разработчиком**. Их проверяет владелец вручную по шагам 11–14 со своим публичным
sitekey. Удалённые анкеты не создавались; Cloudflare, базы и боты не менялись.
