# Контракт API v2

Реализован в полном `wedding-rsvp-api.js`, проверен локально. Действующий Worker ещё не заменён. Основной сайт **не загружает** `rsvp-session.mjs`, endpoint остаётся пустым. Простого изменения endpoint недостаточно: адаптер, Turnstile и UI персональной ссылки подключаются следующим отдельным этапом.

## Общие правила

- `Origin` должен точно совпадать с `ALLOWED_ORIGIN`, например `https://zakkhorren.github.io`, без `/wedding/`.
- Query string отклоняется. Ключа редактирования в URL запроса быть не должно.
- Чтение/сохранение: `Authorization: Bearer <ключ base64url, 43 символа / 32 случайных байта>`.
- JSON, CORS, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. DELETE публичному API недоступен.
- `submissionId` и `requestId` — UUID; ключ генерируется Web Crypto на устройстве гостя. В базе хранится SHA-256 от `id:key`.
- Legacy-записи сохраняются в базе/статистике/CSV. Если ключа нет или его формат неизвестен, угадывание ID не позволяет присвоить или изменить такую анкету.

## GET /rsvp/bootstrap

Без ключа. Возвращает `{ok:true,protocol:2,epoch:"..."}`. Epoch меняется при подтверждённом удалении и защищает от случайного повторного создания старых тестовых анкет.

## POST /rsvp

Один маршрут для создания и обновления. Пример тела (значения в угловых скобках получает клиент):

```json
{
  "submissionId": "b48f3059-7be2-468b-a637-324df9966be8",
  "requestId": "3c539677-a327-4fdf-91f3-e32efc71d032",
  "revision": 0,
  "epoch": "<из bootstrap>",
  "turnstileToken": "<свежий токен виджета с action rsvp>",
  "name": "Семья",
  "attending": "Да, конечно!",
  "guestCount": 3,
  "additionalGuests": "Имена остальных",
  "drinks": ["Виски", "Ром"],
  "otherDrink": "Сидр",
  "parking": "yes",
  "carCount": 2,
  "message": "До встречи!",
  "consent": true
}
```

- Создание: `revision:0`. Изменение: последняя ревизия из GET/POST. Более свежая версия не перезаписывается молча.
- Повтор после ошибки сети: те же ID/ключ/requestId/revision/epoch/ответы. Токен Turnstile может быть новым. Уже выполненный запрос возвращает квитанцию без повторной записи и без повторной проверки потраченного токена, **но после проверки владельца**.
- Тот же requestId с другими ответами — конфликт. Новое изменение после успешного сохранения получает новый requestId.
- Запись, квитанция и задания Telegram сохраняются одной D1 batch-транзакцией. HTTP 200 выдаётся только после чтения зафиксированной квитанции.
- Успех: `{ok:true,saved:true,submissionId,revision,epoch,answer,parkingStatus}`. Ключ и хеш не возвращаются.
- При отказе/«позже» сервер сам выставляет `guestCount:0`, исключает напитки, дополнительные имена и парковку.
- Запрос машин может быть больше 8; он получает `pending`. Изменение машин требует нового решения. Только сообщение/напитки/численность людей при неизменных машинах сохраняют одобрение.
- Статусы парковки: `not_requested`, `pending`, `approved`, `rejected`.

## GET /rsvp/{submissionId}

Требует тот же ключ. Возвращает актуальный ответ, ревизию, epoch и парковочный статус.

## Ошибки и восстановление

| Ошибка | Действие |
|---|---|
| 400 `INVALID_ANSWER` | Исправить поля |
| 400 `TURNSTILE_RETRY` | Новый challenge, без смены ID анкеты |
| 401 `EDIT_KEY_REQUIRED`, 403 `EDIT_KEY_INVALID` | Не выдавать/не изменять запись; не создавать автоматически новый ответ |
| 409 `REVISION_CONFLICT`, `REVISION_OR_EPOCH_CONFLICT`, `EPOCH_CHANGED` | Загрузить актуальную версию и явно решить, повторять ли правки |
| 409 `REQUEST_ID_REUSED` | Проверить pending-запрос: другой payload использовал его ID |
| 404 `RESPONSE_NOT_FOUND` при восстановлении, 410 `RESPONSE_DELETED`/`STALE_IDENTITY` | Сообщить об удалении тестовой записи; новую пару ID/ключ создавать только по явному выбору гостя |
| 503/таймаут/неопределённая сеть | Сохранение могло произойти: повторить тот же pending-запрос, не создавать новый ID |

Успех нельзя показывать только по HTTP 2xx: обязательны `ok:true` и `saved:true`.

## Подготовленный клиент

`rsvp-session.mjs` не подключён к гостевой странице. Его использует технический стенд `tests/manual-api.html`.

```js
const session = await openRsvpSession({ endpoint: 'https://TEST-WORKER.workers.dev/rsvp' });
const current = await session.restore();
const saved = await session.save(answer, async () => freshTurnstileToken);
const confidentialLink = session.editLink();
```

- ID/ключ и pending-запрос сохраняются в localStorage до отправки. При недоступном хранилище отправка блокируется.
- Ссылка: фрагмент `#rsvp_id=...&edit_key=...`. Он удаляется из адресной строки до запросов адаптера. В запросах ключ только в Authorization, перенаправления запрещены, referrer отключён.
- `restore({discardPending:true})` явно принимает серверную версию. Отправка другого payload до разрешения запроса с неизвестным исходом блокируется.
- После удаления: `startNewAfterDeletion(true)` — явное создание новой анкеты. Для удалённой импортированной ссылки можно заново открыть адаптер с исходным `pageUrl` и `confirmNewAfterDeletedLink:true`, только после подтверждения пользователя.
- В будущем UI нельзя выводить ссылку в analytics/console/Telegram. Не журналировать Authorization и тела запросов Cloudflare.

## Архив (миграция 0002)

Полная процедура: [ARCHIVE-ROLLOUT.md](ARCHIVE-ROLLOUT.md). Частные административные команды `/archive ID`, `/archived`, `/restore ID`, `/erase ID` доступны в обеих сборках. Изменяющие операции требуют отдельного подтверждения; `/erase` удаляет только одну запись. Массовое удаление отсутствует в финальной сборке.

После успешной проверки edit key архивная анкета возвращает HTTP 409 `RESPONSE_ARCHIVED` для GET и POST, включая повторы ранее сохранённого requestId. Не создавать новую identity: организатор может восстановить прежнюю анкету. Чужой ключ по-прежнему получает 403. На восстановленной записи парковка возвращается в pending, revision увеличивается; клиент должен перечитать запись. В технической странице показано пояснение про архив; основной сайт не подключён.
