# /export: книга Excel вместо CSV

Ветка основана на PR #5 с архивированием. Команда теперь отправляет
`wedding-rsvp.xlsx` с MIME
`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
Это ZIP-пакет OOXML с отдельными workbook/worksheet/styles, а не CSV с другим
расширением. Runtime-зависимости и Node API не нужны.

## Содержимое

- Один лист «Анкеты», прежние 14 колонок с русскими заголовками.
- Все текущие активные анкеты, включая отказавшихся и ожидающих ответа.
  Архивные исключаются существующей SQL-выборкой; ограничения в 500/1000 строк нет.
- Количество гостей, машин и версия — числа. Даты — числовые значения Excel
  с форматом `dd.mm.yyyy hh:mm`, в московском времени (UTC+3).
  Заголовки дат содержат «(МСК)». Время D1 без суффикса трактуется как UTC;
  ISO с часовым поясом учитывает его. Отсутствующие даты пусты, некорректные
  legacy-значения остаются текстом.
- Настроены ширины, перенос длинного текста, выделение и закрепление заголовка,
  фильтр колонок.
- Пользовательские ответы записываются как `inlineStr`. Значения, начинающиеся
  с `=`, `+`, `-`, `@`, табуляции и перевода строки, остаются текстом;
  формулы, гиперссылки, макросы и внешние связи не создаются.
- Поля перечислены явно: ключи редактирования, их хеши, Turnstile, секреты
  и произвольные `extraAnswers` в файл не попадают.

Использована структура из [документации Microsoft SpreadsheetML](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document);
тип текстовых ячеек описан в [Cell / inlineStr](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cell).

## Сборки и внедрение после отдельной проверки

`worker/wedding-rsvp-api.js` — обновлённая тестовая сборка.
`worker/wedding-rsvp-api.production.js` также пересобрана, чтобы исходник и
генерируемые файлы совпадали; она не загружалась.

Если тестовая D1 уже имеет миграции 0001 и 0002 из PR #5, новая миграция
**не нужна**. Для проверки формата достаточно вручную заменить код только
тестового Worker на полный `wedding-rsvp-api.js`, сохранив его binding,
секреты и существующий тестовый webhook. Если PR #5 ещё не внедрён, сначала
выполнить отдельную процедуру [ARCHIVE-ROLLOUT.md](ARCHIVE-ROLLOUT.md).
Основной Worker, базы, бот, webhook и сайт не менять.

После загрузки в тестовую среду вызвать `/export` из разрешённого private-чата
тестового бота. Проверить расширение XLSX, кириллицу при открытии двойным щелчком,
даты, перенос комментария, ширины и отсутствие архивных записей.
В этой задаче никаких удалённых обновлений и сообщений ботам не выполнялось.

## Проверки

```powershell
node scripts/build-worker.mjs
node scripts/build-worker.mjs --without-test-deletes
node --test --test-concurrency=1 tests/*.test.mjs
node tests/miniflare-smoke.mjs
node tests/manual-browser.mjs
```

52 теста: регрессии API/архива/парковки, экспорт обеих сборок, пустая книга,
1600 записей без обрезки, числа/даты, опасные строки, XML-экранирование,
секреты и архивные анкеты. Независимые Python ZIP/XML-парсеры проверяют CRC и
структуру. Для этой части тестов нужен Python 3, дополнительных пакетов нет.

Miniflare проверяет настоящий multipart `sendDocument` в локальном workerd,
без запросов к Telegram, и сохраняет синтетический пример в
`.qa/workerd-export.xlsx`. Он дополнительно прочитан openpyxl 3.1.5 без
предупреждений; проверены русские заголовки, даты, типы ячеек и ширины.
Chromium-проверка прежнего клиентского адаптера также прошла.
Дополнительно файл открыт в установленном Microsoft Excel 16.0 Windows через
COM в режиме только чтения: кириллица в заголовках и ответах, 14 колонок,
ширина комментария, отображение даты и отсутствие формул проверены.
Строка `=HYPERLINK(...)` осталась буквальным текстом.
Повторить необязательную Windows-проверку после Miniflare:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/excel-export.ps1
```

Скрипт открывает только локальный синтетический XLSX, запрещает макросы и
обновление внешних связей, закрывает свою книгу без сохранения. Проверка
ассоциации файлов при двойном щелчке остаётся ручной.
