# Проверки RSVP API v2

## Выполнено локально

1. `node --test --test-concurrency=1 tests/*.test.mjs` — 36 тестов:
   - числовая численность компании, исключение неактуальных полей;
   - статистика компаний/людей/напитков и CSV без секретов;
   - хеш ключа, восстановление в том же браузере и на другом устройстве;
   - повтор после потери ответа, без дубликата записи;
   - Turnstile: успех, timeout/network, истёкший токен, неверный hostname/action;
   - миграция сохраняет старую строку и откатывается при некорректной старой парковке;
   - создание/чтение/обновление, чужой ключ, параллельные запросы одного ID;
   - ревизии и защита от устаревших кнопок, неверного администратора и replay update_id;
   - лимит 8 машин, изменение одобренной заявки, отмена/отказ;
   - заполненная парковка не мешает редактированию только сообщения;
   - очередь Telegram и повторная доставка без повторной анкеты;
   - временное удаление с подтверждением, истечение/отмена/чужое подтверждение;
   - очистка не затрагивает новые/изменённые после предупреждения записи;
   - каскадное удаление квитанций/очереди и обработка старых browser ID;
   - production-сборка физически исключает обработчики удаления;
   - legacy-записи нельзя присвоить по ID, нет ограничения статистики в 500 строк;
   - два независимых SQLite writer-потока не могут подтвердить больше 8 машин;
   - клиентский адаптер совместим с полным Worker: повтор после потери ответа, ссылка на другом устройстве, редактирование без второй записи.
2. `node tests/miniflare-smoke.mjs` — настоящий workerd + локальный D1: миграция batch сохраняет legacy-строку, создание/чтение/редактирование/повтор, два одновременных подтверждения, подтверждённое удаление и каскад внешних ключей.
3. `node tests/manual-browser.mjs` — Chromium + workerd/D1: технический стенд, создание компании из 3 человек, конфиденциальная ссылка в новом browser context, восстановление и изменение на 2 человека, одна строка в базе, без ошибок JavaScript.
4. `node tests/company-browser.cjs` — проверка существующей демо-анкеты на 320, 375, 390, 430, 768, 1024, 1440 px (счётчик, условные поля, payload, подтверждение сохранения). Реальный endpoint не подключается.

Siteverify и Telegram во всех тестах подменены. Реальные API, команды бота и Cloudflare-база в тестах не использовались. Конкурентные проверки выполнены на независимых SQLite-соединениях, а дополнительно — в runtime workerd/D1.

## Обязательные проверки после ручной загрузки тестового сервера

Реальные Turnstile hostname/action и разрешения виджета; правильность DB binding и Secrets; Telegram webhook `message` + `callback_query`; права администраторов/private chat; Cron доставки очереди. Локальные тесты не заменяют эти облачные проверки.

Доставка сообщений Telegram — как минимум один раз: сетевой таймаут после фактической доставки может дать повтор уведомления. Это не создаёт повторную анкету, не меняет число людей/машин и не повторяет административное действие.

Ни реальные данные, ни действующий Worker не менялись. Основная анкета остаётся демо до отдельного подключения.
