# Проверки RSVP API v2

## Выполнено локально

1. `node --test --test-concurrency=1 tests/*.test.mjs` — 36 тестов:
   - числовая численность компании, исключение неактуальных полей;
   - статистика компаний/людей/напитков и CSV без секретов;
   - хеш ключа, восстановление в том же браузере и на другом устройстве;
   - повтор после потери ответа, без дубликата записи;
   - Turnstile: успех, timeout/network, истёкший токен, неверный hostname/action;
   - миграция сохраняет старую строку и откатывается при некорректной старой парковке;
   - создание/чтение/обновление, чужой ключ, параллельные запросы одного ID;
   - ревизии и защита от устаревших кнопок, неверного администратора и replay update_id;
   - лимит 8 машин, изменение одобренной заявки, отмена/отказ;
   - заполненная парковка не мешает редактированию только сообщения;
   - очередь Telegram и повторная доставка без повторной анкеты;
   - временное удаление с подтверждением, истечение/отмена/чужое подтверждение;
   - очистка не затрагивает новые/изменённые после предупреждения записи;
   - каскадное удаление квитанций/очереди и обработка старых browser ID;
   - production-сборка физически исключает обработчики удаления;
   - legacy-записи нельзя присвоить по ID, нет ограничения статистики в 500 строк;
   - два независимых SQLite writer-потока не могут подтвердить больше 8 машин;
   - клиентский адаптер совместим с полным Worker: повтор после потери ответа, ссылка на другом устройстве, редактирование без второй записи.
2. `node tests/miniflare-smoke.mjs` — настоящий workerd + локальный D1: миграция batch сохраняет legacy-строку, создание/чтение/редактирование/повтор, два одновременных подтверждения, подтверждённое удаление и каскад внешних ключей.
3. `node tests/manual-browser.mjs` — Chromium + workerd/D1: технический стенд, создание компании из 3 человек, конфиденциальная ссылка в новом browser context, восстановление и изменение на 2 человека, одна строка в базе, без ошибок JavaScript.
4. `node tests/company-browser.cjs` — проверка существующей демо-анкеты на 320, 375, 390, 430, 768, 1024, 1440 px (счётчик, условные поля, payload, подтверждение сохранения). Реальный endpoint не подключается.

Siteverify и Telegram во всех тестах подменены. Реальные API, команды бота и Cloudflare-база в тестах не использовались. Конкурентные проверки выполнены на независимых SQLite-соединениях, а дополнительно — в runtime workerd/D1.

## Обязательные проверки после ручной загрузки тестового сервера

Реальные Turnstile hostname/action и разрешения виджета; правильность DB binding и Secrets; Telegram webhook `message` + `callback_query`; права администраторов/private chat; Cron доставки очереди. Локальные тесты не заменяют эти облачные проверки.

Доставка сообщений Telegram — как минимум один раз: сетевой таймаут после фактической доставки может дать повтор уведомления. Это не создаёт повторную анкету, не меняет число людей/машин и не повторяет административное действие.

Ни реальные данные, ни действующий Worker не менялись. Основная анкета остаётся демо до отдельного подключения.

## Проверка архива, ветка fix/archive-restore-review

Основа: PR #4, commit `7fecd41`. 47/47 автоматических тестов проходят (`node --test --test-concurrency=1 tests/*.test.mjs`). Дополнительно прошли `node tests/miniflare-smoke.mjs` (реальный локальный workerd/D1, обе миграции, archive/restore) и `node tests/manual-browser.mjs` (Chromium, техническая форма, восстановление и редактирование).

Проверены: отмена отказа при заполненных 8 местах; устаревшие callbacks; архивирование approved-заявок на 1/7/8 машин; освобождение мест; восстановление в pending; защита SQL от прямого восстановления в approved; гонка двух администраторов; гонка архива с редактированием; private/admin ограничения, отмена и истечение подтверждений; исключение архива из списков/CSV/очереди; отказ публичному клиенту RESPONSE_ARCHIVED; отдельное erase и каскады в финальном Worker; отсутствие массового удаления в финальном файле. Сохранены проверки старых команд, Turnstile, авторизации, идемпотентности, сетевых ошибок, уведомлений, лимита парковки и числового guestCount.

Ошибка исходного CSV-теста PR #4 исправлена: Blob.text() удалял BOM при декодировании тестовым mock. Теперь проверяются исходные байты, отдельно разбираются все 14 колонок с кавычками, точкой с запятой, кириллицей, переносами и нейтрализацией формул. Реальный Excel Windows ru-RU не запускался — нужна ручная проверка.

Ни Cloudflare, ни удалённая D1, ни Telegram webhook, ни рабочий сайт при этих проверках не изменялись. Реальные тестовые анкеты не удалялись. Результаты относятся к локальной среде с mock внешних запросов; реальная доставка Telegram и настройки тестовых секретов проверяются владельцем после ручного внедрения по ARCHIVE-ROLLOUT.md.

## Экспорт XLSX, ветка fix/xlsx-export

Команда /export заменена на полноценный OOXML XLSX: 14 русских колонок, текстовые пользовательские ответы, числовые счётчики и даты Excel по МСК, ширины и переносы. Архивные записи и секреты исключены. Новых миграций нет. Сборки пересобраны из единого исходника, без Node API и runtime-зависимостей.

Результат: 52/52 автоматических теста; реальный локальный workerd/D1 с проверкой multipart sendDocument; Chromium-регрессия клиентского адаптера; независимая проверка ZIP CRC/XML; чтение openpyxl 3.1.5 без предупреждений. В установленном Excel 16.0 Windows синтетическая книга открыта только для чтения: русские заголовки и ответы, 14 колонок, ширины, отображение даты и отсутствие формул проверены. HYPERLINK из сообщения остался буквальным текстом. Тест Windows воспроизводится через tests/excel-export.ps1 после Miniflare. Ассоциация файлов при двойном щелчке отдельно не проверялась.

Проверены пустая книга, 1600 записей без обрезания, недопустимые даты, спецсимволы XML, начальные знаки формул, отсутствие внешних связей/макросов, исключение архивных анкет и реальных тестовых ключей из файла в обеих сборках. Все прежние автоматические проверки продолжают проходить. Реальные Cloudflare, D1, боты и webhook не изменялись. Подробнее: XLSX-EXPORT.md.
