# Wedding longread — базовый свадебный сайт-приглашение

Одностраничный адаптивный сайт в стиле референса: молочный фон, малиновая рукописная типографика, фотоколлаж, календарь, анимированный маршрут тайминга, место свадьбы, палитра дресс-кода, интерактивный конверт и RSVP-анкета.

**Демо-контент — вымышленный.** Сайт можно использовать как старт и полностью поменять тексты, изображения, имена, дату и блоки.

## Быстрый запуск

- Откройте `index.html` двойным кликом или через Live Server в Codes / VS Code. Сборка, Node.js и платные сервисы не требуются.
- Дату, имена, тексты параметров, фото и место меняйте в `site.config.js`.
- Для настоящих фотографий положите JPG/WebP в `assets/` и поменяйте в `site.config.js` соответствующие пути на `assets/название.webp`.
- Сейчас показаны 3 демонстрационных фотографии по URL Unsplash. Они требуют подключения к интернету, а при недоступности отображаются стилизованные заглушки.
- Общие тексты лонгрида меняются в `index.html`, оформление — в `styles.css`, анимации и RSVP — в `script.js`.

## GitHub Pages (отдельный репозиторий)

1. Создайте **новый публичный репозиторий** на GitHub, например `wedding-longread` (не трогайте репозиторий портфолио).
2. Загрузите все файлы из папки стартера, включая `.github/workflows/pages.yml` и `.nojekyll`, в корень нового репозитория. Ветка — `main`.
3. В GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. GitHub Actions после пуша опубликует сайт. Ссылка обычно вида `https://USERNAME.github.io/wedding-longread/`.
5. Следующие изменения в ветке `main` обновят сайт автоматически.

Так как пути относительные, проект работает и в корне домена, и на GitHub Pages в репозитории-подпапке.

## RSVP: куда пойдут ответы

**По умолчанию сайт работает в DEMO-режиме.** Отправка формы проверяет ввод и показывает подтверждение, **но данные никому не уходят и не сохраняются**. Это сделано намеренно, чтобы при тестировании не терять персональные данные и не показывать ложное подтверждение доставки.

Для работающей формы укажите `rsvpEndpoint: 'https://...` в `site.config.js` после подключения защищенного обработчика. Формат отправки — `POST` с JSON: `name`, `attending`, `additionalGuests`, `drinks`, `food`, `message`, `createdAt`, `consent`.

### В Telegram-бота

В папке `worker/telegram-worker.js` лежит пример Cloudflare Worker, который принимает HTTPS POST и отправляет сообщение в Telegram. В Cloudflare Worker настройте:

- Secrets (не в коде): `BOT_TOKEN` и `CHAT_ID`.
- Environment variable `ALLOWED_ORIGIN` — полный origin публичного сайта, например `https://USERNAME.github.io` (без пути `/wedding-longread`).
- Разместите Worker, получите HTTPS URL, вставьте его в `site.config.js` как `rsvpEndpoint`.
- Проверьте работу реальной отправки в Telegram, прежде чем раздавать ссылку гостям.

**Важно:** токен бота и ID получателя не храните в `site.config.js`, HTML, JS, GitHub или в открытых GitHub Secrets, которые попадают на клиент. GitHub Pages — статический хостинг, нужен отдельный серверный обработчик. Проверка origin через CORS сама по себе не полноценная защита от спама: для реального потока добавьте Turnstile/rate limiting и правила обработки персональных данных.

### На почту

Можно использовать Formspree, Getform или собственный serverless-обработчик, который отправляет email. Сервис должен принимать JSON POST и возвращать HTTP 2xx при успехе; проверьте поддержку CORS для домена GitHub Pages. После настройки вставьте endpoint в `site.config.js`. Не вставляйте SMTP пароль в публичный сайт.

## Проверка перед отправкой гостям

Заменить демонстрационные имена, дату, тайминг, адрес и фотографии; проверить ссылку на карты и .ics-календарь; настроить форму и доставку; проверить отображение на телефонах и согласие гостей на обработку их данных.
