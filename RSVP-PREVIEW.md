# Проверка настоящей RSVP-формы — этап A, без публикации

Ветка `feat/rsvp-preview` основана на PR #6 (`2126f18`). Обновлена существующая
форма в `index.html`, а не техническая анкета. Фотографии, остальные секции,
календарь, маршруты и анимации не заменялись.

**Ничего не развёрнуто:** основной сайт и `main` остаются в демо-режиме.
Оба удалённых Worker, D1, webhook и боты не изменялись; агент не отправлял
удалённые тестовые анкеты. Миграции и серверный код в этой ветке не меняются.

## Открыть предварительную версию

Нужны Node.js 24+ (проверено на 26.13), Python 3 для полного набора тестов и
Chromium из Playwright для интерактивного просмотра. В текущем общем рабочем каталоге можно
сразу перейти в подготовленный worktree:

```powershell
cd .worktrees/rsvp-preview
node scripts/preview-rsvp.mjs
```

Если проверка выполняется в другой копии репозитория, не переключайте грязную
рабочую ветку и не делайте merge в main. Создайте отдельный worktree:

```powershell
git fetch origin
git worktree add --detach ../wedding-rsvp-preview origin/feat/rsvp-preview
cd ../wedding-rsvp-preview
npm install --no-save --package-lock=false playwright miniflare
npx playwright install chromium
node scripts/preview-rsvp.mjs
```

По умолчанию открывается **полностью локальная** проверка. Настоящий код Worker
работает в Miniflare/D1 на компьютере; Turnstile и Telegram заменены локальными
заглушками. Вводить можно только тестовые данные. За пределы компьютера ответы
не передаются. Перезагрузка страницы восстанавливает ответы, пока это окно
открыто. После закрытия локальная временная база не сохраняется.

### Проверить именно существующий тестовый Worker

После просмотра локальной версии владелец может открыть её с настоящим
тестовым API. Нужен **публичный sitekey** Managed Turnstile, соответствующий
уже настроенному secret тестового Worker и hostname `zakkhorren.github.io`.
В репозитории этого публичного ключа нет; secret вводить сюда нельзя.

```powershell
node scripts/preview-rsvp.mjs --test-api --sitekey ВАШ_ПУБЛИЧНЫЙ_SITEKEY
```

Этот режим отправляет вручную заполненные ответы в
`https://wedding-rsvp-api-test.zakk-horren.workers.dev/rsvp`.
Используйте только тестовые ответы; существующие настройки тестового Worker
должны указывать на его тестовую D1 и тестового бота. Обновлять Worker, менять
bindings, миграции, секреты или webhook для этой проверки не требуется.

Инструмент открывает отдельный профиль Chromium и **только в этом окне**
подставляет локальные файлы вместо GitHub Pages. В адресной строке остаётся
`https://zakkhorren.github.io/wedding/?rsvp_preview=1`, поэтому существующие
CORS и проверка hostname Turnstile продолжают работать. Origin, Siteverify и
секреты не подменяются. Файлы никуда не загружаются; обычный браузер других
гостей видит прежний публичный сайт. Закройте окно, чтобы остановить просмотр.

Профиль настоящей тестовой проверки сохраняется в `.qa/rsvp-test-api-browser`
(вне Git). Повторный запуск с той же командой восстанавливает ответ из того же
браузера. Не публикуйте папку профиля и персональные ссылки.

Дополнительные варианты:

```powershell
# Узкое окно 390 px:
node scripts/preview-rsvp.mjs --test-api --sitekey ВАШ_ПУБЛИЧНЫЙ_SITEKEY --mobile
# Другой независимый браузер для проверки персональной ссылки:
node scripts/preview-rsvp.mjs --test-api --sitekey ВАШ_ПУБЛИЧНЫЙ_SITEKEY --fresh-browser
```

Скопируйте персональную ссылку кнопкой в успешной анкете и вставьте её
**в адресную строку второго изолированного окна**, не в терминал и не в логи.
На другом компьютере сначала запустите тот же просмотр из этой ветки.
Пока ветка не опубликована, ссылка в обычном публичном браузере ещё не может
показать новую форму: там остаётся демо. На телефоне предварительный просмотр
проверяется эмуляцией ширины; публичная мобильная публикация не выполнялась.

Если Turnstile не загружается или проверка не завершается, форма показывает
ошибку и не подтверждает отправку; валидация сервера не ослабляется.
Автоматические проверки используют заглушки, как рекомендует
[Cloudflare для автоматизации](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

## Что изменено в анкете

- Подключён существующий `openRsvpSession`: bootstrap, restore, save и editLink.
  Старый несовместимый POST без ID/ключа удалён.
- Отправка разрешена только при **двух условиях**: `?rsvp_preview=1` и
  `rsvpPreview.enabled === true`. По умолчанию enabled=false, endpoint основного
  сайта пуст. Один заполненный endpoint или одна персональная ссылка не
  включают сетевую отправку. Preview принимает только точный адрес тестового API.
- Managed Turnstile: explicit render, action `rsvp`, одноразовый токен,
  повторная проверка при истечении, понятные ошибки и повторные попытки.
  Compact/interaction-only не расширяет страницу на 320 px.
  Настройки основаны на [документации Cloudflare](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/).
- Сохранение считается успешным только после подтверждения `saved:true`.
  Парковка показывается по ответу API: pending не означает бронь.
- После сохранения: прежний экран благодарности, персональная ссылка,
  копирование с ручным fallback и кнопка редактирования этой же анкеты.
- При повторном открытии ответы автоматически загружаются из API по сохранённой
  identity. Фрагмент личной ссылки удаляется до динамических импортов и
  запросов адаптера. Запросы не содержат ключ в URL, referrer отключён.
- При неоднозначной ошибке отправки исходные ответы и requestId остаются
  в localStorage. Форма временно блокируется от новых правок; можно повторить
  **тот же** запрос либо явно загрузить актуальную запись.
- Конфликт revision/epoch не стирает правки. Загрузка актуальной записи
  требует подтверждения замены локального содержимого.
- Архив не предлагает новую анкету. Удалённый/устаревший ID можно заменить
  только после явного подтверждения; новый ответ сам не отправляется.
- Условные поля очищаются/отключаются при отказе и «позже». Счётчик остаётся
  числовым, выбор напитков множественный, свой напиток сохраняется отдельно.
- Компактное поле сообщения растёт по содержимому и корректно пересчитывается
  при изменении мобильной ширины. Шрифты, палитра и существующие SVG сохранены.

## Повторяемые проверки

```powershell
node --test --test-concurrency=1 tests/*.test.mjs
node tests/rsvp-form-browser.mjs
node tests/rsvp-form-errors.mjs
node tests/company-browser.cjs
node tests/manual-browser.mjs
node tests/miniflare-smoke.mjs
node scripts/preview-rsvp.mjs --smoke
```

- 53 unit/integration-теста: прежние backend/XLSX/архив/парковка и адаптер.
- 12 сценариев реальной формы в Chromium с настоящим локальным workerd/D1:
  demo gate, отключённый preview, отсутствие sitekey, создание, копирование,
  редактирование, конфликт после административного подтверждения парковки,
  отмена/подтверждение загрузки, перезагрузка, другая браузерная identity,
  потеря ответа после COMMIT с перезагрузкой и повтором того же requestId,
  «нет»/«позже», архив, явное начало новой анкеты после удаления.
- 9 сценариев ошибок: сеть при bootstrap, просроченный токен с новым токеном
  и тем же requestId, отсутствие saved:true, заблокированные Turnstile и
  localStorage, потеря сети до COMMIT с восстановлением неподтверждённого ввода,
  повреждённая/неверная персональная ссылка и устаревший ID после смены epoch.
- Ширины 320, 375, 390, 430, 768, 1024, 1440 px; переполнение, условия,
  растущая textarea. Скриншоты в `.qa/rsvp-preview-*.png` и
  `.qa/rsvp-success-*.png` не входят в Git.
- Прежняя демо-форма, технический адаптер, серверные тесты и preview launcher
  проверяются отдельно. Реальные удалённые данные в этих тестах не используются.

Это подготовка этапа A. Реальный тест с публичным sitekey выполняет владелец
после проверки PR. Production-cutover, резервная копия D1, обновление основного
Worker и публикация сайта — отдельный последующий шаг по явному разрешению.
Не объединять PR в main автоматически: push/merge main запускает Pages.
