# Промт для Codex / Codes — дальнейшая работа над сайтом

Ты — опытный frontend-разработчик и motion-дизайнер. Продолжай разработку уже существующего в этом репозитории одностраничного сайта свадебного приглашения. НЕ переписывай все с нуля и НЕ меняй творческое направление без запроса. В папке уже есть рабочий MVP на обычных HTML/CSS/JS, готовый к GitHub Pages.

## Референс

Референс — присланное мной вертикальное видео свадебного лонгрида. В нем светлый кремовый фон, малиновый цвет, очень живая рукописная типографика, бумажные коллажи, два детских фото пары с яркой обводкой, календарь, плавная извилистая линия тайминга, фотография локации в полароидной рамке, скотч/скрепка, палитра цветов дресс-кода, анимированный розовый конверт и малиновый блок RSVP.

Цель — максимально воспроизвести КОМПОЗИЦИОННУЮ ЛОГИКУ и взаимодействия референса, а не просто создать тематический лендинг. Страница — цельная вертикальная история. Никаких карточек в духе корпоративного сайта, шаблонных градиентов и ненужного меню.

## Что уже есть

- Адаптивная верстка, демонстрационные данные и фото-заглушки.
- Анимации проявления блоков и прогресс чтения.
- Динамический календарь с отмеченной датой и скачиванием .ics.
- Тайминг с прорисовывающейся по скроллу кривой.
- Фото локации, палитра дресс-кода, интерактивный конверт.
- Рабочий frontend формы RSVP с DEMO-режимом, в котором **данные никуда не отправляются**.
- Пример Cloudflare Worker для безопасной доставки RSVP в Telegram.
- GitHub Actions для GitHub Pages.

## Задачи

1. Проверь весь сайт в Chromium на ширинах 320, 375, 390, 768, 1440 px. Исправь переполнения, наложения, типографику и ритм.
2. Доведи анимации до аккуратного, плавного поведения: текст мягко появляется при прокрутке; линия тайминга действительно рисуется по мере скролла; на мобильных нет дерганий; проверь `prefers-reduced-motion`.
3. Сделай замену фото пары максимально удобной. В финале будут наши фотографии — желательно возможность изображений с прозрачным фоном и мягкой малиновой обводкой/контуром, а не просто прямоугольники.
4. Сохрани дизайн как в референсе: кремовый + насыщенный малиновый, рукописные заголовки и пометки, скотч, бумажные элементы, сердечки, фото-полароид, раскладка блоков.
5. Все тексты, фотографии, имена, даты и адрес должны легко заменяться. Тестовые данные пометь как демонстрационные.
6. Финальная форма должна позволять ввести имя гостя, отметить присутствие, указать дополнительные имена, предпочтения напитков и пожелания. Раздел с дополнительными вопросами скрывать, если гость не придет. Поля валидировать, показывать честное состояние доставки.
7. Сайт должен оставаться **статическим и пригодным для GitHub Pages**. Не добавляй обязательный серверный runtime или платные зависимости. Секреты Telegram нельзя встраивать в JS браузера. При дальнейшем подключении использовать защищенный backend/Cloudflare Worker или email form endpoint.
8. После каждого законченного изменения делай коммит в НОВЫЙ репозиторий этого свадебного сайта. Публикуй на GitHub Pages после проверки и сообщай публичную ссылку. **Не трогай существующий репозиторий моего портфолио.**

Не придумывай фактические имена, реальные адреса, даты или фотографии, если я их еще не передала. Заполняй нейтральными демо-значениями. Не сообщай, что что-то опубликовано, пока не подтвердил реальную GitHub Pages ссылку.
